# S47 deterministic photographs and native UI tour

The generator creates eight RGB8 PNG photographs from one unsigned 32-bit seed: two single photographs, a three-frame moving-subject exposure bracket, and a three-frame panorama with 48-pixel world-space overlap. It downloads no asset, model, profile, or library. The manifest declares generated pixels CC0-1.0.

Within the bracket, the world-scene seed and all non-subject pixels are stable. The only scene motion is the declared subject rectangle. Exposure is exactly `2^exposure_stops` before RGB8 encoding: the even, unsaturated background uses integer floor division at -1 EV and exact doubling at +1 EV; the foreground uses the declared RGB8 saturation rule. Generator controls decode all foreground and background pixels, including the +1 EV foreground saturation point. Within the panorama, adjacent camera crops retain identical bytes across their declared 48-pixel overlap.

Each of two independent UI launches creates a distinct demo catalog, imports the original generated photographs, opens `single-harbor.png`, and waits for an accessibility marker emitted only when the current selected catalog asset, its working-version source identity, and the active editor document agree. The test expects `single-harbor.png|master|160x120`, retains an editor capture, observes the ordinary public Quit command terminate the app, then rehashes every source original. Each fresh catalog is named `Demo.catalog` within the fixture root's `WorkingVersions` folder, one path for both tours: the catalog sidebar displays the working-version folder's full path (up to two lines), so any per-tour difference in that path, such as a run number, would differ in the captures wherever the path is not truncated. Each tour is its own test invocation (`testS47DeterministicDemoCatalogTourOpensPhotoEditorAndRetainsItsCapture`, with `LW_S47_TOUR_RUN` 1 or 2), and the folder is a new real, empty, mode-0700 directory for each, prepared by the fixture owner (below). After the normal photo route creates its distinct UUID-named working version, the tour uses the ordinary File → Save As… sheet to save `single-harbor.comp` in that same owned folder, outside the catalog directory. It checks the actual saved source record, complete native original and VariantKey, distinct working-version ID, preserved original source record, and current loaded marker before capture. Each tour attaches its exact capture PNG bytes, its typed window-domain record (whose `pngSHA256` names those bytes) and a tour record (`lensworks.s47.tour-record.v1`: run, working folder, fixture original hashes after the observed Quit) to its own result bundle. After each tour, the owner exports that bundle's attachments with `scripts/ci/export_s47_tour_capture.py`, which selects the run's domain and tour records and the one PNG whose SHA-256 the domain record names (missing, ambiguous or mismatched attachments fail) and writes them exclusively as `run-<N>.png`, `run-<N>-domain.json` and `run-<N>-tour.json` under the owner's 0700 capture root (`LW_S47_CAPTURE_ROOT`). The two retained captures are compared only after both complete tours finish, in a third invocation (`testS47DeterministicDemoCatalogToursCompareConsecutiveRetainedScreenshots`), which checks each capture against its domain record (run, loaded marker, PNG digest, pixel size, window geometry), that both tours used the same working folder and pinned frame and retained identical fixture originals that still match the manifest, and produces an independently measured maximum channel delta and nonzero-pixel changed fraction over the complete dense RGBA8 images.

CI uses the maintained self-hosted Apple-silicon runner, then verifies its provisioned `DEPENDENCIES.json` pkg-config and Homebrew inventory plus the checksum-pinned DNG SDK before building owned helpers and the shared `CompositorUITests` scheme. The workflow transports every LensWorks value as `TEST_RUNNER_LW_*`; Xcode removes that host prefix and the UI test reads delivered `LW_*` values before forwarding the helper paths and XCTest configuration to the application. CI delivers both thresholds from the checked-in measured `S47_SCREENSHOT_TOLERANCE.json` through the purpose-specific loader and `GITHUB_ENV`, then Xcode transports their `TEST_RUNNER_LW_*` names. Repository variables supply no separate implicit defaults. The declared bounds remain unaccepted until the fresh thresholded tour and actual CI smoke pass.

The fixture-owner shell runs the generator before XCTest; it creates `WorkingVersions` as an empty mode-0700 directory under the exclusive fixture root (the generator's default; `--working-folder` names others, as the S38 fixture's `WorkingVersions-1` … `-4`). Between the tours the owner moves the used folder to `WorkingVersions-tour1` (retained as evidence) and creates `WorkingVersions` again with `mkdir -m 700`; after tour 2 it moves that one to `WorkingVersions-tour2`. The sandboxed UI runner checks the real directory, its mode and its emptiness before each launch, and performs no fixture or external report writes. Calibration (`testS47DeterministicDemoCatalogToursMeasureRetainedPairWithoutToleranceAcceptance`) measures the same two retained tour captures and retains the entire typed JSON record as the `S47-calibration-report.json` XCTest attachment with `public.json` type and `keepAlways` lifetime. After the native test is terminal, the root exports attachments from that exact xcresult and exclusively publishes the complete attachment bytes as its report; missing or ambiguous attachments fail artifact qualification. Calibration remains `MEASURED_NOT_ACCEPTED` and supplies no implicit screenshot threshold.

The current declared bounds are maximum byte-channel difference 0 and changed-pixel fraction 0, measured from two fresh complete same-host tour pairs whose four editor-window captures were byte-identical. Each tour launches with `-LensWorksPinnedWindowFrame`, which pins the editor window to one 1280×800-point frame on the primary display, disables frame autosave and restoration, and puts an opaque app-owned backdrop behind the window's rounded corners; the test also warps the pointer to the primary display before launch, asserts that exact frame and waits for the sidebar to list both working versions before capturing. Without the pin, CI run 38139318825 restored an earlier autosaved frame and opened one tour on the 2x built-in display and the other on the 1x external display, so the captures had different pixel sizes; without the backdrop, the corners showed whatever other apps had behind them. The previous bounds (191 and 665/1,729,728) came from a pair whose catalog names and document titles differed per run, which the current tour no longer does. On the self-hosted VM runner, CI run 39625472520 showed per-run working folders (`WorkingVersions-1`, `WorkingVersions-2`) do the same: their short path fit the sidebar's two lines, so the trailing digit differed (36 pixels, delta 124); on the earlier host the longer path was truncated before it. Both tours therefore use one folder path, recreated between them. These exact numbers carry no guessed margin or ignored pixels and are not a population noise estimate or acceptance on another host. No automatic relaxation on failure or post-hoc acceptance is allowed. Every future capture still needs its full typed window-domain record and independent actual image inspection. Actual CI evidence remains required for S47.
